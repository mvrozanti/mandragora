# `gokapi/` — file drop (public links, gated upload)

Stack for `share.mvr.ac`. Gokapi file-share server: drop a file (or a
tarball of files), get a public unguessable download link with expiry
by time and/or download count.

This is the "between `serve` and seafile" tier: bigger reach than the
LAN-only `serve` alias, lighter than seafile's sync/share flow, and —
unlike `microbin` at `clip`/`paste` — download links are reachable by
anyone with the URL (no Authelia prompt for the recipient). `microbin`
stays for text/code snippets; `gokapi` handles files.

## Container

| Container | Image | Port | Persistence |
|---|---|---|---|
| `gokapi` | `f0rc3/gokapi:latest` | `53842` (in-container) | `./config` → `/app/config`, `./data` → `/app/data` |

Like `microbin`, `gokapi` runs on the VPS in `seafile-net`, so the
VPS-side caddy reaches it directly by container name — no `socat` shim.

## Auth model — asymmetric by path

Gokapi runs in **authentication method `Disabled`** (`Method: 3` in
`config/config.json`): the app performs no auth of its own and treats
every request that reaches it as super-admin. Access control is
therefore delegated entirely to caddy, split by path:

- **Admin / upload UI / session routes** (`/admin`, `/apiKeys`,
  `/uploadChunk`, `/logs`, `/users`, `/filerequests`, `/setup`, …) are
  behind Authelia `forward_auth` (`@protected` matcher, handle 0). Only
  the owner, after TOTP, reaches them.
- **Everything else** (handle 1, catch-all) is public: the download
  pages (`/d/…`, `/dh/…`), raw downloads (`/downloadFile`, `/hotlink`,
  `/h/…`), static assets, and the REST API (`/api/*`).

`/api/*` is intentionally public at caddy because Gokapi gates it with
its own **API key** — so `curl -H "apikey: …" -F file=@x share.mvr.ac/api/files/add`
works from anywhere without an Authelia session. Mint keys from the
(Authelia-gated) admin UI.

This mirrors the `axon` / `music` "trust Authelia" proxies: the app has
no internal gate, caddy is the gate. If a caddy path matcher is ever
wrong, admin is exposed — the `@protected` list is the security
boundary, treat it as such.

## Ready out-of-the-box (no setup wizard)

Gokapi normally opens a browser setup wizard on first start and refuses
to boot until a super-admin exists in its SQLite DB. Both are pre-seeded
here so `docker compose up -d` just works on a fresh machine:

- `config/config.json` — the config the wizard would have written
  (`Method: 3`, `ServerUrl https://share.mvr.ac/`, local storage,
  `MaxFileSizeMB 20480` = 20 GB). Its presence makes Gokapi skip setup.
- `data/gokapi.sqlite` — seeded with the single super-admin row
  (`admin@gokapi`, Userlevel 0) so the boot-time user check passes.
  Password is irrelevant in `Disabled` mode; no plaintext secret.

Both were generated by driving the setup form once headlessly, then
folding the WAL and stripping test data — committed as the reproducible
seed. Uploaded file blobs and the log are gitignored; only the seed
DB is tracked.

## Verification

- `curl -sI https://share.mvr.ac/admin` → `302 → auth.mvr.ac/?rd=…`.
- `curl -sI https://share.mvr.ac/d/<id>/<name>` (public, no auth) →
  `200` once a file with `<id>` exists.
- Upload from anywhere with an API key:
  `curl -F file=@./f -H "apikey: <key>" https://share.mvr.ac/api/files/add`
  → JSON with `FileInfo.UrlDownload`.
